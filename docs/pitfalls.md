# 踩坑紀錄

`AGENTS.md` 只保留這份檔的路徑。坑寫在這裡，不要寫回 `AGENTS.md`。

新遇到的坑加在「本專案已遇到」的最上面。每一則包含：日期、現象、原因、對策、影響哪一步。

## 本專案已遇到

### 2026-10-03 暫停預覽仍然每幀用 GPU

- 現象：用過「輸出 ASS」之後，Electron 的 GPU 仍然約三成，片停咗都唔跌。
- 原因：寫 ASS 冇轉碼。預覽同進度條一打開就用 requestAnimationFrame 不停重畫，暫停都係。存檔窗關閉，個視窗返到最前，迴圈繼續跑。
- 對策：暫停同播完就畫一幀然後停。播緊、拖字幕、改外觀、跳時間、字體載入、視窗大細變，先再畫。進度條同樣只喺播緊時跟住走。視窗大細變動少過兩點唔當再畫，避免畫面大細來回跳。
- 影響：預覽。

### 2026-10-03 輸出 ASS 唔好只寫 karaoke.ass

- 現象：使用者想拎一份字幕檔走。
- 原因：匯出 MP4 把 `karaoke.ass` 寫喺專案旁邊。ffmpeg 的 `ass=` 濾鏡用呢個相對名。下次匯出會覆蓋佢。
- 對策：「輸出 ASS」另存使用者揀的路徑，內容同燒進去的字幕。匯出 MP4 仍然寫 `karaoke.ass`。
- 影響：輸出 ASS。

### 2026-10-03 文字頁刪唔到一句，Ctrl+Z 亦復原唔到

- 現象：文字頁的時間欄冇辦法刪走一句。改詞、插入、呢句時間之後，Ctrl+Z 冇反應。
- 原因：淨係延遲同速度各自有上一步。重設呢句係清返改動，唔係刪句。歌詞同譯文係受控輸入，瀏覽器的復原唔會改到時機。
- 對策：刪除呢句藏起原句、拿走插入句。文字頁有成個時機的上一步，Ctrl+Z 一樣。長按仍係一步。歷史喺 setState 外面記，避免 Strict Mode 記兩次。LRC 草稿欄唔截 Ctrl+Z。外形頁唔聽。
- 影響：文字頁時機。

### 2026-10-02 全選拖飛入的字會變成成首拖

- 現象：撳咗全選，拖預覽有時位置唔會照全選走。飛入開頭最明顯。
- 原因：拖曳只量句尾定位。飛入開頭的字離句尾幾十點，撳落可見的字多數唔中，就當成拖空白，原文同譯文一齊走。兩塊疊住時又先中原文，譯文畫在上面但唔郁。全選的開關如果喺更新畫面之前就清掉，按鈕仍然亮住，拖曳已經變返逐句。
- 對策：先抓而家畫住嘅字，再抓句尾定位。重疊時譯文先中。全選狀態等畫面更新完先通知預覽。拖緊唔好用舊畫面蓋住位置。
- 影響：0.6 全選拖曳、0.7 飛入。

### 2026-10-02 時間軸長句會蓋住譯文

- 現象：原文太長時，文字頁同效果頁的時間軸會疊字。譯文被壓住，成列都睇得亂。
- 原因：每一行高度固定，方便捲動時只畫可見的幾行。原文可以換行，但行高唔會變，多出來的字就畫到譯文同下一行上面。
- 對策：時間留喺左邊。原文同譯文各自一行，過長就收尾。滑鼠停上去先見到全句。
- 影響：時間軸。

### 2026-10-03 貼住臨界的直排成片仍然偏疏

- 現象：直排成片的字心距離貼住最高那隻字之後，睇落仍然疏。
- 原因：臨界係「中」這類高字剛剛貼住。平常的字矮過佢，中間仍然有空。
- 對策：字體頁有成片間距。預設 −2，即再密兩點。0 先至係量到的臨界。拉桿由 −8 到 8，只影響直排匯出。預覽步進未改。未寫過就係 −2，寫低的 0 要保留。使用者話差不多了。
- 影響：直排成片疊字。

### 2026-10-02 直排成片字距拉唔開疊字

- 現象：垂直排列、預設字距，預覽每隻字分開。匯出 MP4 之後字同字疊住。字距拉到較大仍然改善不多。
- 原因：預覽的筆畫置中，裙邊只有一半伸出字格，步進用字級加字距就夠。成片先把字級放大到「國」的墨水約等於字級，`\bord` 再整段露在字外。預設裙邊 6，上下一共多 12 點。常用字比「國」更高，光柵化再多約 2 點。字距最多 8，補唔返。步進如果改成放大後的 `\fs`，空隙會過大。
- 對策：成片直排的字心距離係字級加字距，再加兩倍裙邊，再加該款字體量到的臨界。昭源、正黑、雅黑加 4，字級 64、裙邊 6 就係 80。標楷加 10，同一組就係 86。字級 24 的昭源只超出 2，用 4 會剩 2 點。收窄只縮字級同字距，裙邊同臨界超出維持原值。預覽步進未改。小點仍然用字數乘字級。裙邊預設仍然係 6。
- 影響：0.10 字距、0.13 自動收窄的直排匯出。

### 2026-10-02 放大的 \fscx 會蓋住收窄

- 現象：長句又揀咗放大，收窄開頭被蓋住，動畫完彈返全寬，字又伸出畫面。小點如果跟著加 `\fscx` 會變扁。
- 原因：libass 後寫的 `\fscx` 蓋住前面的。放大的 `\t` 目標係 `\fscx100`，會抵消收窄。`\fscx` 亦會一齊縮樣式字距。量過：字距 0 的一行闊 222，`\fscx50` 變 112；字距 40 的一行闊 582，`\fscx50` 變 292，約一半。
- 對策：橫排把收窄乘入放大的 `\fscx`，高度仍然由 82 去到 100。小點唔加 `\fscx`，改用收窄後的長度擺位。直排改字級同步進，唔再寫第二個 `\fscx`。
- 影響：0.13 自動收窄。

### 2026-10-02 橫排成句的原文跟咗譯文字體

- 現象：改原文字體，預覽嘅原文冇變。改譯文字體，原文同譯文一齊變。
- 原因：量度譯文寬度會把 `ctx.font` 設成譯文。冇逐字、冇字距、冇漸邊的原文係成句去畫，自己唔再設字體，就用咗譯文嗰款。
- 對策：量完寬度設返原來的字體。畫成句原文之前再設一次原文字體。
- 影響：0.12 譯文字體。

### 2026-10-02 fontsdir 唔會擋住系統字體

- 現象：匯出的 `fontsdir` 只放昭源圓體，成片仍然燒到標楷、微軟正黑、微軟雅黑。
- 原因：libass 的 `fontsdir` 係額外目錄，唔係取代系統字。這部電腦用 DirectWrite，認到樣式名 `KaiTi`、`Microsoft JhengHei`、`Microsoft YaHei`。
- 對策：譯文沿用現有四款，唔打包華康、方正、冬青。樣式名保持英文。冇裝呢幾款的電腦，成片可能退回其他字。對片在 `studio-data/font-check/font-check.mp4`，唔好提交。
- 影響：0.12 譯文字體。

### 2026-10-02 擺正的預覽同成片轉去相反方向

- 現象：預設「擺正」如果直接把角度交俾 Canvas，開頭會同匯出的成片側去另一邊。
- 原因：ASS 的 `\frz` 正數係逆時針。Canvas 的 `rotate` 正數係順時針。同一個 −6 度，兩邊唔同邊。
- 對策：預覽畫的時候反號。匯出仍然寫 `\frz-6`。
- 影響：0.7 擺正。

### 2026-10-02 垂直排列唔好順手改位置

- 現象：揀左垂直或右垂直之後，句子仍然橫排，只係成首位置跳去左邊或右邊。
- 原因：排列切換時如果成首位置仲係預設，就改寫 x、y。畫面先見到搬位。直排要逐隻字由上寫到下，同左右位置係兩件事。
- 對策：排列只得橫排同垂直。揀垂直唔改 x、y。預覽同匯出都按字由上疊落。舊檔的 left、right 讀成 vertical；如果仲停喺自動靠位，位置返去預設。
- 影響：0.6 位置。

### 2026-10-02 句子位置再讀一次會偏離成首

- 現象：已經單獨擺過的句子，重新打開之後離成首更遠，或者成首一拖，句子走了兩倍。
- 原因：`enter.x`、`enter.y` 有兩種意思。沒有 `basis: "look"` 時是畫面絕對位置，打開時減去成首位置變成偏移。已經是偏移又再減一次，距離就錯。
- 對策：新寫入的片段帶 `basis: "look"`。`settleClip` 見到這個標記就不要再減成首位置。
- 影響：0.6 位置。

### 2026-09-24 匯出用的暫存檔名以 `.part` 結尾，ffmpeg 認不出封裝格式

- 現象：匯出「海奏ララバイ」時，ffmpeg 報 `Error initializing the muxer for ...\.海奏ララバイ.mp4.part: Invalid argument`，沒有成片。
- 原因：暫存檔從 `out.part.mp4` 改成 `.${歌名}.mp4.part`。ffmpeg 用最後一段副檔名挑封裝，`part` 對不上 mp4。檔名以點開頭也容易被當成隱藏檔。
- 對策：暫存檔是 `海奏ララバイ.part.mp4`。副檔名留在最後，檔名不以點開頭。寫完再改名成 `海奏ララバイ.mp4`。
- 影響：M8 匯出。

### 2026-09-24 打包後匯出，ass 濾鏡被字體路徑裡的空格切斷

- 現象：用 `release\win-unpacked\LyricVideo.exe` 匯出測試片，畫面停在 `Error parsing filterchain 'ass=karaoke.ass:fontsdir=C\:/Users/Leo/Lyric\ Video/release/win-unpacked/resources/fonts'`，接著打不開 `out.part.mp4`，回報 `Invalid argument`。沒有 `out.mp4`。
- 原因：ffmpeg 的 ass 濾鏡用冒號和空格切參數。字體在 `Lyric Video\release\...\resources\fonts`。把磁碟機冒號寫成 `C\:`、空格寫成 `\ ` 仍會斷，ffmpeg 會說 `No option name near '/Users/Leo/Lyric Video/...'`。開發時字體和片子在同一棵樹，相對路徑 `../../fonts` 沒有空格，所以先前能匯出。
- 對策：濾鏡的 `fontsdir` 只放 `[A-Za-z0-9._/-]` 這種相對路徑，工作目錄仍是該片資料夾。打包後相對路徑含空格時，先把字體複製到 `%AppData%\lyric-video\export-fonts`，濾鏡用 `../../export-fonts`。不要改回絕對路徑跳脫。
- 影響：M7 匯出。

### 2026-09-24 `npm install` 之後 Electron 本體不在

- 現象：`npm run dev` 報 `Error: Electron uninstall`。`node_modules/electron` 有套件，沒有 `path.txt` 和 `dist/electron.exe`。
- 原因：二進位要由套件裡的 `install.js` 另外下載。這次 `npm install` 沒有把它留下。
- 對策：在專案目錄執行 `node node_modules/electron/install.js`。不要改 npm 的 `ignore-scripts`。
- 影響：M0 開視窗。

### 2026-09-24 electron-vite 5 不能配最新的 Vite 8

- 現象：一次安裝 `electron-vite` 和 `@vitejs/plugin-react` 時，npm 報 ERESOLVE。`@vitejs/plugin-react` 6 要 Vite 8，`electron-vite` 5 只接受 Vite 5 到 7。
- 原因：兩個套件的 peer 範圍沒有交集。
- 對策：鎖 `electron-vite@5`、`vite@7`、`@vitejs/plugin-react@5`、`vitest@3`。不要為了過安裝加 `--force`。
- 影響：M0 的依賴。以後升級 electron-vite 再一起看 Vite。

- 現象：`git config user.name` 和 `user.email` 都是空的。直接 commit 會停下來問你是誰。

### 2026-09-24 在專案目錄執行 git，卻碰到 `C:\` 的儲存庫

- 現象：當時本目錄還沒有 `.git`。執行 `git status` 向上找到 `C:\`，並因擁有者是 `NT SERVICE\TrustedInstaller` 而報 dubious ownership。
- 原因：Git 會向上找 `.git`。這個專案自己的儲存庫尚未建立。
- 對策：只在 `C:\Users\Leo\Lyric Video` 裡 `git init` 和提交。不要執行 `git config --global --add safe.directory C:/`。不要在 `C:\` 做任何 git 操作。
- 影響：文件這一步通過人手驗證之後的第一個 commit。

## 從 DesktopLyric 帶過來的約束

下面這些已在 DesktopLyric 發生過。本專案直接遵守，不要用實作再試一次來確認。

- 網易雲舊的 `/api/search/get` 會忽略關鍵字。搜尋用 `cloudsearch`。
- YouTube 的 mix、長片用整段時長對歌會配錯。20 秒以下或 12 分鐘以上的時長不用來對歌詞。
- 連唱、空檔、譯文配對、快慢步進那些常數改了，現場版和雙語行會整批錯位。
- 網易雲 YRC 常把日文和中文壓在同一行，要拆開，中文當譯文。逐字超過 80 個就不要再做逐字高亮。
- 時機介面若每一拍都重建清單或把當前句捲進畫面，會卡、會跳。清單虛擬化，捲動不要跟著播放走。
- 模糊陰影在桌面歌詞的分層視窗上曾弄垮繪圖。這裡的歌詞用描邊，不做模糊陰影。
- `%AppData%\DesktopLyric\` 是已發行程式的資料。讀寫會弄髒使用者的桌面歌詞。
