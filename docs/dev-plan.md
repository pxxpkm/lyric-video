## 已定範圍

一句話：一條 YouTube 音樂連結或本機影音，自動配上同步歌詞，先預覽，按了「匯出 MP4」才出 1080p 檔。

技術：Electron + TypeScript + React（electron-vite）、yt-dlp、ffmpeg、昭源圓體。歌詞行為從 DesktopLyric 移植成 `src/core` 的純函式，用 vitest 鎖住。對照基線是 `C:\Users\Leo\src\DesktopLyric` 的 `922aaea`，119 項測試當時全過。那個專案凍結，不引用它的 exe。

程式目錄：

```
src/core       解析、時機、簡轉繁、歌名、評分、ASS、專案 schema
src/main       Electron、yt-dlp、ffmpeg、四源 HTTP、專案讀寫
src/renderer   匯入、揀歌、預覽、時機、匯出
src/shared     候選、專案、進度事件
tests/core
dict/          STCharacters.txt、STPhrases.txt、HKVariants.txt
fonts/         昭源圓體，附授權
studio-data/   使用者的片和輸出，不進 git
```

流程停在預覽，不是停在檔案：

`匯入 → 清理歌名 → 四源搜詞 → 評分 → 夠自信就採用 → 套用已記住的時機 → 打開預覽`

不夠自信、搜不到、或片長不能拿來對歌，才進揀歌。時機就在預覽旁邊改，改完當幀能看到。匯出按鈕在預覽畫面，有本地媒體和歌詞才能按。連續數條網址時，每一條都停在預覽，沒按匯出的不會有 MP4。

自動對歌比桌面歌詞有利：yt-dlp 先拿到標題、上傳者和時長，再走同一套 `SearchTitle` / `SearchArtist`（「」、（歌／歌手）、`- Topic`、TV サイズ、OP 標題）。人可以分開鎖歌名或歌手再搜。

預覽和成片共用 `src/core` 的時間軸（這一毫秒是哪一句、亮到哪個字）。預覽是 Canvas，成片是 ASS 燒進影片，像素可以差幾粒，時間和用字必須一致。音訊模式用封面加暗角的底圖再燒同一份 ASS，不用 ffmpeg `showwaves`。解析度墊成 1920×1080。

歌詞在抓到時寫進該片的 `project.json`。之後斷網也能預覽和匯出。翻譯只在抓詞當下跑一次，失敗就空著，可以手改。時機形狀沿用 `TrackTiming`：整首偏移和快慢、逐句 shift、停留、改詞、插入、譯文。存檔在 `%AppData%\LyricVideoStudio\`。重新搜詞會換掉歌詞快照；對不上的逐句修改保留偏移和快慢，並標成要人看。

自動採用的起始門檻（M2 寫死並有測試，三首歌手測後只改這一處）：清理後歌名相似度 ≥ 0.75；時長可用時相差 ≤ 8 秒；第一名 ≥ 0.82 且比第二名至少高 0.08。記住過而且仍抓得到的候選直接用。長片一律不自動採用。

四源並行，一家失敗不影響其他家：網易雲 `cloudsearch`、QQ、酷狗、LRCLIB。每源 8 秒逾時。v1 只做 Windows x64、單條，不做播放清單、Mac、Linux、上傳。

## 里程碑

每步結束都先跑該步的測試，再請你按「人手驗證」做。你說通過才 commit，才開下一步。

### M0 骨架

electron-vite、空的 `src/core`、`project.json` 的 schema、log 目錄、renderer 不開 nodeIntegration、專案檔先寫暫存再改名。

- 自動測試：一份假 `project.json` 通過 schema；故意寫壞的檔不會覆蓋好的那份。
- 人手驗證：執行開發指令後出現一個視窗，上面只有產品名和「尚未匯入」。關掉視窗後沒有 `studio-data/` 裡的 MP4。

### M1 歌詞核心

LRC、YRC、時機數學、歌名清理、簡轉繁、choice key。不連網。xunit 裡 WinRT 壽命那些測試不移植。

- 自動測試：對應斷言改成 vitest 並通過。
- 人手驗證：不需要開視窗。你指定一句要看的輸入（例如一條帶「」的 YouTube 標題，或一小段 LRC），我把輸入和輸出貼在這份檔的過程紀錄裡，你核對歌名或時間戳。

### M2 搜詞與評分

四個 provider 只用錄好的 JSON。評分和自動採用。

- 自動測試：該採用的會採用；長片和低相似度會拒絕；一家來源拋錯，其他家仍有結果。
- 人手驗證：過程紀錄貼兩組假結果的分數和「採用／拒絕」。你看拒絕的那組是不是長片或歌名不像。

### M3 匯入

yt-dlp 先取 metadata 再下載，ffprobe 寫時長，建立該片目錄和 `project.json`。匯入畫面可改、可分開鎖歌名和歌手。≥12 分鐘預設音訊模式並說明原因。

- 自動測試：標題清理和「長片不用時長」用假 metadata，不連網。
- 人手驗證：貼一條你自己的音樂網址，或拖一個本機檔。畫面上在下載完成前就看得到清理後的歌名。磁碟上有媒體檔和 `project.json`，沒有 MP4。下載失敗時，畫面叫你改拖檔，而不是停住。

### M4 預覽

這是匯出前的必經畫面。媒體和歌詞一定下來就進預覽。沒有歌詞也可以播，畫面寫「尚未有歌詞」，匯出按鈕不能按。

預覽可以播放、暫停、拖拉。歌詞跟 `currentTime`：當前句大、下一句淡、譯文細，有 YRC 就逐字亮。有畫面就疊在畫面上，音訊模式疊在封面底圖上。

這一步同時做兩件用來給人驗的東西：

- 可關掉的時間讀數：目前毫秒、句鍵、亮到第幾個字。
- 一支程式產生的約 10 秒測試片（純色加短聲）和一份固定 LRC，不靠 YouTube 也能驗同步。

- 自動測試：給定時間，core 算出來的句和亮字跟預期一致。
- 人手驗證：打開測試片，播放、暫停、拖拉到中間。時間讀數會變，歌詞跟聲音走。整段看完，專案目錄裡仍然沒有 MP4。若你另有本機歌，用同一畫面再播一次。

### M5 時機

整首偏移和快慢、逐句 ±50ms、停留、改詞、插入、復原、LRC 匯入匯出。清單虛擬化，不跟著播放自動捲。寫入節流約 200ms。改完可從該句前約 2 秒重播。

- 自動測試：偏移、快慢、停留後的顯示時間；復原回到上一份時機；重新讀檔與寫入相同。
- 人手驗證：用測試片把某一句撥早 50ms，畫面立刻變，時間讀數變。重開程式，這 50ms 還在。按復原可以回到沒撥之前。

### M6 匯出

同一條時間軸產生 `karaoke.ass`（`\k` 厘秒、譯文第二行、昭源圓體），再 ffmpeg：libx264 CRF 18、preset medium、aac、`+faststart`，墊成 1920×1080，帶 `fontsdir`。沒有逐字就整句顯示，不偽造逐字。進度走 `-progress`。轉碼時預覽仍可播。

按匯出時先把 `karaoke.ass` 寫進該片目錄，然後才開始 ffmpeg。

- 自動測試：有逐字的句子，`\k` 總長等於句長，容許 1 厘秒。
- 人手驗證：先看測試片的預覽，再按匯出。未按之前沒有 MP4；按了之後有進度，完成能用播放器打開，看得到歌詞。用記事本打開 `karaoke.ass`，抽一句對一下時間。另外拿一條 ≥12 分鐘的片（或假 metadata）確認它預設音訊模式，而且沒有用片長自動配詞。

### M7 打包與連續佇列

electron-builder win-x64、設定（繁體、譯文；羅馬字開關可先只留位置）、崩潰 log。數條網址順序跑，每一條停在預覽。同一時間只轉碼一條，而且只轉按過匯出的那條。

- 人手驗證：在沒有開發指令的情況下打開打包好的 exe，走一次測試片的預覽。再放兩條工作，確認沒按匯出的那條沒有 MP4。

不納入這八步：Whisper 或 stable-ts 對拍、播放清單、Mac/Linux、像素級錄製 Canvas 當第二條匯出路徑。對拍以後只准寫進 `TrackTiming` 的逐句時間，不准取代已抓到的歌詞用字。

## 改善空間

這些還沒排進上面的里程碑。要做的時候先改這份檔，把某一項移進某一步，再開始。不要改 `AGENTS.md`。

- 匯出前用測試片做一次「只比較時間軸、不比較像素」的檢查清單，避免以後為了像素差去改 ASS。
- 評分門檻在中、日、英各一首真的預覽過之後再調。調的時候只動 M2 那一處常數，並把舊數字留在過程紀錄。
- 時機編輯加鍵盤：左右 50ms，按住加速沿用 DesktopLyric 的按住步進。手指對 Live 版會比滑鼠快。
- 可選的除錯：預覽上標出「這句是自動採用還是人手揀的」和分數，方便你判斷門檻緊不緊。
- 崩潰後下次啟動打開 `run.log` 的尾段。現在只要求 log 有寫。
- 從 DesktopLyric 的 `choices.json` 匯入一次。預設不做，因為那會讀已發行程式的資料。
- 逐幀把 Canvas 灌進 ffmpeg，換取跟預覽相同的像素。只有在 ASS 的樣式不夠用時才做，v1 的風格刻意收在 ASS 做得到的範圍。
- 唱歌語音辨識只用來挪時間。它常常改壞歌詞用字，所以不能當 v1 的詞來源。
