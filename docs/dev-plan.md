### 0.6 已驗過

1. 打開測試片，或任何已有歌詞的片子。還沒單獨擺過的句子停在成首位置，也就是字體的預設左右、上下。
2. 闊畫面時，預覽佔左面大部分，「文字」和「外形」喺右面，可以捲動。直畫面或窄窗時，預覽喺上面，選項喺下面，而且選項會左右分欄。文字頁是歌詞、譯文、延遲、速度、呢句和停留。外形頁的字體和效果可以各自收起。效果預設打開，裡面有字幕時間軸，可以揀句，但沒有延遲、速度、呢句和停留。沒有自由文字。時間讀數唔再蓋住畫面；開咗就喺進度條下面，格式係幾分幾秒。
3. 撳住原文拖動，只移動呢句原文。撳住譯文拖動，只移動呢句譯文。畫面不再顯示下一句。撳字幕以外的畫面拖動，成首原文同成首譯文一齊走，已經分開的距離保持不變。已經單獨擺過的句子保持同成首的距離。句子之間的空檔，成個畫面都是成首拖動。
4. 再拖一次空白。先前單獨擺過的那句仍保持那段距離。
5. 字體的原文左右、上下，同拖空白係成首原文。譯文左右、上下係成首譯文，兩邊各自移動。左右可以拉到畫面最左同最右。效果裡面沒有位置控制桿。拖空白會原文同譯文一齊走，已經分開的距離保持不變。
6. 效果的時間欄有「全選」。撳下去之後，時間欄每一句都亮起。喺預覽拖原文，全部原文一齊走；拖譯文，全部譯文一齊走，全選保持開住。成首位置用字體的控制桿。淡入、淡出和「跟字體」套用到每一句。再撳一次全選，或揀返一句，就回到逐句。
7. 字體有「排列」：橫排、垂直。垂直由上寫到下，逐隻字疊住，字不側轉。原文同譯文可以分開擺，橫排都一樣。例如日文放左側、中文放右側。拖日文只移動日文，拖中文只移動中文。字體沒有「下一句」。匯出的成片用同一個位置。
8. 淡入拉高，開頭更淡；淡出拉高，結尾更淡。位置不變。「跟字體」之後，這句回到成首位置，淡入淡出也清掉。之後再拖空白，這句跟住走。
9. 按「匯出 MP4」。句子在成片裡停著，不會滑動。有淡入淡出的會變透明。直排的句子在成片裡亦由上寫到下。取消就不會轉碼。
10. 找一份還沒有 `motion` 的舊 `project.json` 打開。預覽跟 beta 0.5 一樣，排列是橫排。這輪已經逐句擺過的片子，打開時位置先不變；之後成首拖動會帶住它們。
11. 字體頁可以分開調原文字級、原文顏色、譯文字級、譯文顏色。改一邊，另一邊留喺原位。原文唱到只作用喺原文。字體款式同裙邊兩邊共用。匯出用同一個字級同顏色。舊檔未分開時，譯文字級跟以前的譯文比例，譯文顏色跟當時的原文顏色。

測試：179 項通過。TypeScript 檢查通過。

## 已定範圍

一句話：一條 YouTube 音樂連結或本機影音，自動配上同步歌詞，先預覽，按了「匯出 MP4」才出 1080p 檔。

技術：Electron + TypeScript + React（electron-vite）、yt-dlp、ffmpeg、昭源圓體。歌詞行為從 DesktopLyric 移植成 `src/core` 的純函式，用 vitest 鎖住。對照基線是 `C:\Users\Leo\src\DesktopLyric` 的 `922aaea`，119 項測試當時全過。那個專案凍結，不引用它的 exe。

程式目錄：

```
src/core       解析、時機、簡轉繁、歌名、評分、ASS、進場出場、專案 schema
src/main       Electron、yt-dlp、ffmpeg、四源 HTTP、專案讀寫
src/renderer   匯入、揀歌、預覽、時機、匯出
src/shared     候選、專案、進度事件
tests/core
dict/          STCharacters.txt、STPhrases.txt、HKVariants.txt
fonts/         昭源圓體，附授權
studio-data/   使用者的片和輸出，不進 git
```

流程停在預覽，不是停在檔案：

`匯入 → 清理歌名 → 四源搜詞 → 評分 → 夠自信就採用 → 套用已記住的時機 → 打開預覽`

不夠自信、搜不到、或片長不能拿來對歌，才進揀歌。時機就在預覽旁邊改，改完當幀能看到。匯出按鈕在預覽畫面，有本地媒體和歌詞才能按。連續數條網址時，每一條都停在預覽，沒按匯出的不會有 MP4。

自動對歌比桌面歌詞有利：yt-dlp 先拿到標題、上傳者和時長，再走同一套 `SearchTitle` / `SearchArtist`（「」、（歌／歌手）、`- Topic`、TV サイズ、OP 標題）。人可以分開鎖歌名或歌手再搜。

預覽和成片共用 `src/core` 的時間軸（這一毫秒是哪一句、亮到哪個字）。預覽是 Canvas，成片是 ASS 燒進影片，像素可以差幾粒，時間和用字必須一致。音訊模式用封面加暗角的底圖再燒同一份 ASS，不用 ffmpeg `showwaves`。解析度墊成 1920×1080。

歌詞在抓到時寫進該片的 `project.json`。之後斷網也能預覽和匯出。翻譯只在抓詞當下跑一次，失敗就空著，可以手改。時機形狀沿用 `TrackTiming`：整首偏移和快慢、逐句 shift、停留、改詞、插入、譯文。存檔在 `%AppData%\LyricVideoStudio\`。重新搜詞會換掉歌詞快照；對不上的逐句修改保留偏移和快慢，並標成要人看。

自動採用的起始門檻（M2 寫死並有測試，三首歌手測後只改這一處）：清理後歌名相似度 ≥ 0.75；時長可用時相差 ≤ 8 秒；第一名 ≥ 0.82 且比第二名至少高 0.08。記住過而且仍抓得到的候選直接用。長片一律不自動採用。

四源並行，一家失敗不影響其他家：網易雲 `cloudsearch`、QQ、酷狗、LRCLIB。每源 8 秒逾時。v1 只做 Windows x64、單條，不做播放清單、Mac、Linux、上傳。

## 改善空間

這些還沒排進上面的里程碑。要做的時候先改這份檔，把某一項移進某一步，再開始。不要改 `AGENTS.md`。

- 匯出前用測試片做一次「只比較時間軸、不比較像素」的檢查清單，避免以後為了像素差去改 ASS。
- 評分門檻在中、日、英各一首真的預覽過之後再調。調的時候只動 M2 那一處常數，並把舊數字留在過程紀錄。
- 時機編輯加鍵盤：左右 50ms，按住加速沿用 DesktopLyric 的按住步進。手指對 Live 版會比滑鼠快。
- 可選的除錯：預覽上標出「這句是自動採用還是人手揀的」和分數，方便你判斷門檻緊不緊。
- 崩潰後下次啟動打開 `run.log` 的尾段。現在只要求 log 有寫。
- 從 DesktopLyric 的 `choices.json` 匯入一次。預設不做，因為那會讀已發行程式的資料。
- 逐幀把 Canvas 灌進 ffmpeg，換取跟預覽相同的像素。只有在 ASS 的樣式不夠用時才做，v1 的風格刻意收在 ASS 做得到的範圍。
- 唱歌語音辨識只用來挪時間。它常常改壞歌詞用字，所以不能當 v1 的詞來源。
